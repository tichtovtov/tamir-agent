Message flow

Free text: parser first, language model second

Free text that parser.parse doesn't recognize goes to nlu.OllamaNLU.interpret (a language model in Ollama), which returns an Interpretation. A bare number while a question is pending also goes to the model, so it can be read as the answer.

The model only interprets; the code decides

Every currency the model returns goes through _resolve (aliases + catalog + the rates provider's list). An unrecognized currency → a question to the user. A settings change → only after a button press.

Conversation memory

When the bot asks a question (the model's question, "which currency?" for a bare number, or an image without a currency), the exchange is stored in context.user_data, in memory only. The next message goes to the model together with the memory, so יורו or 50 is understood in context. It is cleared after a successful action or after CONVERSATION_TTL_SECONDS (10 min), and holds at most CONVERSATION_MAX_MESSAGES.

If Ollama is down

Unrecognized text gets the help message (same as before the feature). Regular conversions aren't affected.

Choosing a currency in /set and /from

Implemented in _choose_currency in handlers.py:

  1. No argument → quick-pick buttons (catalog.POPULAR); in /from, also a cancel button.
  2. Code / symbol / alias (currencies.normalize) that the rates provider supports → saved directly.
  3. Otherwise catalog.search by name or country: one match → saved; several → selection buttons; none → error plus a pointer to /currencies.

A button press arrives as a callback query with data set:<code> / from:<code> / from:off, handled by currency_button, which validates the code again before saving.

Modules (bot/)

currencies.pyMap of symbols/names → ISO code (for parsing free text), and display formatting
catalog.pyCatalog of ~50 common currencies: Hebrew/English name, flag, region, countries. Used for /currencies, search, and buttons
rates.pyRatesClient: fetches USD-based rates, cache, conversion via cross rate
ollama.pyOllamaClient: shared Ollama client (chat with a JSON schema, startup check of models)
vision.pyOllamaVision: sends an image to the model and returns ParsedPrice
nlu.pyOllamaNLU: interprets free text into an Interpretation (action + fields), given the user's settings and first name. Includes SYSTEM_PROMPT with examples
messages.pyAll user-facing texts (Hebrew, HTML)

Services are created once in __main__.py and stored in application.bot_data["services"] (a Services object).

Data files (data/, not in git)

FileWho writes itFormat
allowed_users.jsonAdmin, by hand{"<telegram_id>": {"name": "<name>"}}
bot_users.jsonThe bot (admin's /add_user, /remove_user){"<telegram_id>": {"name": "<name>", "added_by": <admin id>, "added_at": "<ISO time>"}}
user_prefs.jsonThe bot{"<telegram_id>": {"name": "<Telegram name>", "currency": "USD", "source": "EUR"}}

currency = target currency (default DEFAULT_CURRENCY). source = default source currency from /from, optional; /from off removes the field.

The allow-list is the union of allowed_users.json and bot_users.json; if a user is in both, the name from allowed_users.json wins.

Admins (ADMIN_IDS in .env) always pass the gate and can run /add_user, /remove_user and /users. For anyone else these commands fall through to the help message, like an unknown command. The admin commands are added to the Telegram command menu only in admins' private chats (BotCommandScopeChat).

Design decisions

Polling, not a webhook

No public address or SSL certificate needed. Works behind a home NAT.

Local Ollama

Images and text never leave the machine, and there's no per-use cost. The JSON schema in format forces structured output.

Parser first, model second

Common messages (100 USD) are answered immediately and deterministically; only what isn't recognized pays the ~6 seconds of the language model.

Rates via USD

A single API call gives the rate between any pair of currencies: rate = rates[target] / rates[source].

Stale cache when the API fails

Better to return an old rate, with a warning, than to fail.

A broken allowed_users.json doesn't lock out users

The previous list is kept.

How to extend

New way to write a currency in free text
Add an entry to ALIASES in currencies.py (lowercase key), plus a test in tests/test_parser.py. Only unambiguous names (e.g. not "דינר"; those are handled by search with buttons). An alias must not be exactly a magnitude suffix (k, m, b, bn, אלף, מיליון...), because the parser reads those as multipliers first.
Currency in the list / search by country
Add _c(...) to CATALOG in catalog.py (code, Hebrew name, English name, flag, region, search keywords). For a quick-pick button, also add it to POPULAR.
Currency display symbol
DISPLAY_SYMBOLS in currencies.py.
Changing text wording
messages.py only.
Improving recognition from images
Change PROMPT in vision.py, or the model in .env. Use LOG_LEVEL=DEBUG to see the model's raw output.
Improving free-text understanding
Add an example to the Examples section of SYSTEM_PROMPT in nlu.py. Check with real phrases (see tests/test_nlu.py for the format), not just the ones in the examples.
New action for the language model
Add it to ACTIONS and to the prompt in nlu.py, handle it in _understand in handlers.py, and add a test in tests/test_handlers.py.
New admin command
Like a new command, but start the handler with the _is_admin check (fall back to help_cmd) and add it to ADMIN_COMMANDS instead of COMMANDS, plus a line in messages.ADMIN_HELP.
New command
A function in handlers.py + registration in register() + an entry in COMMANDS in __main__.py (so it shows in Telegram's menu) + a line in the help text.
Different rates provider
Replace _fetch in rates.py (keep self._rates relative to one base currency).

Tests

tests/ covers the logic without network access: parsing, conversion and cache (httpx.MockTransport), the allow-list and preferences (temp directory), the vision and language modules (a mocked Ollama), and the handlers' logic, including the clarifying-question and confirmation flow (test_handlers.py, with stub Telegram objects).
